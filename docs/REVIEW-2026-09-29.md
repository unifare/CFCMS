# 代码审查：多语言不变量在「多语言 / 多站点」维度上的存活性

审查日期：2026-09-29 · 基线 commit `0fe23da` · 审查者：AI（读真实代码，逐条核验）

**审查目标**（用户原话）：「确保后面的开发任务里不会丢失多语言这个事实。能放错。架构清晰。
不耦合。通用。扩展强。强契约。」

**结论**：分层与契约的**骨架是好的**（依赖倒置用了三次、词汇表单点定义、守卫测试在跑），
但**「多语言事实」在四个地方靠约定而非靠类型/契约维持**。约定会腐化。
下面 4 个高危项全部经过实读验证，并给出「何时会爆」的具体场景。

---

## 0. 一句话风险表

| # | 高危点 | 位置 | 性质 | 现在为何没爆 |
|---|---|---|---|---|
| **H1** | `tableDelete` 删掉**该行所有语言**的翻译 | `table-facade.ts:338-341` | 数据丢失（不可逆） | 单语言时看不出差异 |
| **H2** | 主题 Worker 从**可伪造的请求头**取 `siteId`，兜底 `"default"` | `runtime-worker.ts:297` | 跨站串数据 | 本地只有 default 站 |
| **H3** | `o.siteId ?? "default"` 兜底**绕过架构守卫** | `runtime-declarative.ts:444` | 静默读错站 | 类型上 `siteId` 是必填，`??` 是死代码 |
| **H4** | 4 处 `locale || "en"` 字面量回退 | `api.ts:1027/1207/1209/1210` | 内容读写错语言 | default 站恰好是 en |

**共同病根**：`architecture.test.mjs:244` 的正则只匹配**参数默认值** `siteId = "default"`，
**匹配不到 `?? "default"` 这种兜底表达式**——与本仓库已记录的「同一意图的两种写法」
完全同型。守卫守的是**写法**，不是**语义**。

## H1（最严重）· `tableDelete` 静默销毁其他语言

```ts
// src/extensions/theme/table-facade.ts:338
export async function tableDelete(env: Env, def: ThemeTableDef, id: string): Promise<void> {
  if (def.i18n_table) {
    await env.DB.prepare(`DELETE FROM ${def.i18n_table} WHERE row_id = ?`).bind(id).run().catch(() => {});
  }
  await env.DB.prepare(`DELETE FROM ${def.table_name} WHERE id = ? AND site_id = ?`).bind(id, def.site_id).run();
}
```

三点问题，任一都足够：

1. **签名里没有 `locale`**。作为「数据访问函数」，它违反规则 6 的精神（虽然规则 6 的表层
   检查只盯 `siteId`/`locale` 的默认值）。调用方 `api.ts:945` 传的是 `(env, def, row.id)`——
   **删一行 = 删所有语言**。多语言站上，管理员删掉「日语版」这一行，中文/英文版本一起消失。
2. **`WHERE row_id = ?` 没有 `site_id` 收窄**。主表那条有 `AND site_id = ?`，
   侧表这条没有。如果 `row_id` 恰好跨站碰撞（生成表 id 若非全局唯一），会删到别的站。
   **一个函数里两条 DELETE 的收窄条件不一致，是明确的缺陷，不是风格问题。**
3. **`.catch(() => {})` 吞掉错误**。`_i18n` 删除失败时静默继续，然后主表删成功——
   留下**孤儿翻译行**。设计不变量说 `_i18n` 永不清理，于是这些孤儿永远活着，
   下次同 id 复用时**复活成脏数据**。

> ⚠️ 注意：不要用「`_i18n` 永不删除」去论证这里该保留。不变量的原意是
> **「不因切语言/切主题而销毁数据」**，不是「删行时也必须留副本」。
> 但**删单语言**与**删整行**是两件事，当前代码无法区分——因为签名里没有语言。

**建议**：`tableDelete(env, def, id)` 保持「删整行含全部翻译」的语义**但补 `AND site_id = ?`**，
另加 `tableDeleteTranslation(env, def, id, locale)` 供「只删某语言」；
两者都在 JSDoc 写明语义差异。**关键是让签名承载语义**，而不是让调用方猜。

## H2 · 主题 Worker 信任可伪造的头取 `siteId`

```ts
// src/extensions/theme/runtime-worker.ts:297
const siteId = request.headers.get("x-cfpress-site") ?? "default";
```

对照**正向路径**：前台走 `resolveSite(env, u, sites)`（`index.ts:112`，按 host/路径前缀），
后台走 `requestSiteId(url)`（`api.ts:60`，`?site=`）。
**`handleThemeApi` 是唯一一个数据访问入口，站点来源既不是 host 也不是 `?site=`，而是请求头。**

问题：
- 请求头是**客户端可控**的。真正能约束它的是「谁能调到 `/__cfpress/theme-api/*`」——
  如果这条路由没有绑定到沙箱调用方（如 service binding / 签名），任何能发 HTTP 到宿主的
  客户端都能**指定站点**，即跨站读写。
- 缺头时兜底 `"default"`，意味着**沙箱主题一旦漏传头，就静默操作默认站**——
  正是 AGENTS.md 里 `activeTheme()` 那个缺陷的完全同型：能编译、能运行、**静默读错站点**。

**建议**：`siteId` 必须由**宿主在调用沙箱时注入并验签**，或改为从 URL/路径解析，
**不接受裸头**；缺站点时**拒绝**（4xx）而不是兜底 default。
这条要落成检查：**「所有数据访问入口的 siteId 来源只能是 `resolveSite` 或 `requestSiteId`」**。

## H3 · `?? "default"` 绕过守卫

```ts
// src/extensions/theme/runtime-declarative.ts:444
runQuery: (params, sc) => runThemeQuery(env, params, sc, o.siteId ?? "default"),
```

`o.siteId` 类型是必填，所以 `??` 是**死代码**——但它是**活地雷**：
将来谁把 `siteId` 改成可选，这行不会报错，而是**静默切到默认站**。

同时暴露守卫缺口：

```js
// tests/architecture.test.mjs:244
/\b(siteId|locale)\s*(?::\s*[\w<>[\]| ]+)?\s*=\s*("default"|'default'|[A-Z][A-Z0-9_]{2,})\s*(?=[,)])/g;
```

只匹配 `= "default"` 形式 → **`?? "default"`、`|| "default"`、三元兜底全部漏网**。
`runtime-declarative.ts:225` 的 `String(scope.locale ?? "en")` 同理。

**建议**：守卫**扩到兜底运算符**（`\?\?|\\|\\|`）与三元分支；
并**注入一次违规反向验证**（这是本仓库的既定纪律）。零容忍应该覆盖
「用表达式达到默认值效果」的所有写法，否则它只是把问题从 `=` 挤到了 `??`。

## H4 · 内容语言的 `|| "en"` 字面量回退

```ts
api.ts:1027  const locale = String(url.searchParams.get("locale") || "en");   // search
api.ts:1207  String(b.locale || "en")                                        // revision 写入
api.ts:1209  url.searchParams.get("locale") || "en"                          // autosave 读
api.ts:1210  String(b.locale || "en")                                        // autosave 写
```

`savePost`（`api.ts:201`）**已经被修成**「回退到站点默认语言」，这四处却还是硬编码 `"en"`。
在默认语言为 `zh-CN` 的站点上：搜索查的是 `t.locale='en'`（空结果或错语言），
版本/自动保存**写进 en 行**——内容语言事实被悄悄改写。

**建议**：全部改为 `await siteDefaultLocale(env, siteId)`；并把「回退顺序恒为 当前语言 →
站点默认语言 → 空，不抛错」抽成**一个函数**（`resolveContentLocale(env, siteId, hint)`），
消除四处重复表达（规则 30：同一规则只表达一次）。

## 中危（不致命，但会拖垮「扩展强 / 不耦合」）

### M1 · `setSiteDefaultLocale` 的 500 路径

```ts
// api.ts:715  —— 未包 try/catch
if (b.is_default === true) await setSiteDefaultLocale(env, siteId, code);
// locale-registry.ts:264  —— 直接抛
if (!isLocaleCode(code)) throw new Error(`invalid locale code: ${code}`);
```

路由正则 `^i18n/locales/([A-Za-z0-9-]{2,10})$` 比 `isLocaleCode` **宽**：
`PATCH /api/v1/i18n/locales/12` 能过路由，却在 `setSiteDefaultLocale` **抛未捕获异常 → 500**。
紧邻的 `disableSiteLocale`（720）**包了** try/catch 返回 400。**同一路由两种错误处理**，
是「能放错」的典型：用户拿到 500 而不是「无效语言代码」。
（也违反不变量 6 的精神：语言解析/切换不该炸。）

### M2 · `_i18n` 表名的第二处表达式

```ts
// tables.ts:323
const i18nName = `${def.table_name}_i18n`;
```

权威定义是 `themeI18nTableName()`（`tables.ts:113`）。此处**重算**同一规则——
今天等价，改命名规则时会脱节（规则 30：同一规则只表达一次）。

### M3 · 主题 Worker 的表解析路径与其它路径不同

`runtime-worker.ts:410,442` 用 `resolveThemeTable(env, siteId, themeName, …)`，
**不**走 `resolveTableForSite`。后果：主题切换后，Worker 主题**够不到**已有表，
而后台/前台够得到。这不是命名绕过，是**两条解析路径**——「通用」的反面。

## 低危 / 观察

- `nav.js:149` `applyMenuCustom(groups, custom, locale)` 内部 `locale ? : "en"`。
  调用方必须传**界面语言**，但**没有任何东西强制**它——将来误传内容语言，
  菜单改名会静默换语言（这正是「界面语言 vs 内容语言不得混淆」的破口）。
  建议形参改名 `uiLocale` 并在 JSDoc 标注，或用一个 `UiLocale` 品牌类型。
- `runtime-declarative.ts:140` `if (!name) name = "default"`（主题名兜底）。
  与**站点 id** `"default"` 字形相同，正是 AGENTS.md 记录的 `activeTheme` 陷阱温床。
- `api.ts:1152` 菜单接口用 `siteDefaultLocale` 喂 `resolveUiLocale` 的
  `defaultLocale`——内容默认值参与界面语言候选。当前无害（无包则落 en），
  但两个概念在**同一行**交汇，值得加注释钉住。

## 做得好的地方（别在重构里弄丢）

1. **依赖倒置已用三次**（`contract/hooks.ts`、`i18n/packs.ts`、`admin-menus.ts`）——
   平台只认接口，实现在 boot 注入。这是「不耦合」的实打实成果。
2. **词汇表单点定义**（`contract/manifest.ts`）——测试与后台读同一份，不抄结论。
3. **`table-facade.readProjection` 的 `COALESCE(tr.x, dflt.x, m.x)` 阶梯是单点定义**——
   回退顺序（当前语言 → 站点默认 → 主表）只有一处表达。**H4 应照这个模式收敛。**
4. **`resolveLocale` 的四级优先 + `explicit` 只在路径时为真**——语义想得很清楚，
   且**从不抛错**（符合不变量 6）。
5. **守卫测试真的在跑，并且记录了六种自己的假绿**——这种自我怀疑的纪律比守卫本身珍贵。

## 建议的落地顺序

| 序 | 动作 | 为什么先做 |
|---|---|---|
| 1 | **H1 + H2** 修（补 `site_id` 收窄 / 站点来源不信任裸头） | 唯一两条会造成**不可逆数据损失或跨站串数据** |
| 2 | **扩展架构守卫**：兜底运算符 + 「siteId 来源白名单」；每项**注入违规反向验证** | 让 H2/H3 类问题**从此挡在门外**，而不是这轮修完下轮复发 |
| 3 | H4 抽 `resolveContentLocale()`，四处字面量收敛 | 内容语言是「多语言事实」的核心，重复表达必然脱节 |
| 4 | M1 补 try/catch；M2 改调 `themeI18nTableName()`；M3 统一解析路径 | 一致性 |
| 5 | 低危项按需 | — |

**贯穿全部的一条**：把「多语言事实」从**约定**升级为**类型/契约**——
签名里带 `locale`、品牌类型区分 UI/content locale、单点定义回退阶梯。
凡是靠「记得这么做」维持的不变量，都会在某个未来的任务里被忘记。
